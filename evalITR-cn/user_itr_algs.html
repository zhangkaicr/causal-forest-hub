比较估计的 ITR 与用户自定义 ITR

原文：Compare Estimated and User Defined ITR（英文） · evalITR 官方文档中文译本

本篇讲解如何用 evalITR 把"从数据里估计出来的个体化治疗规则（Individualized Treatment Rule, ITR）"和"由领域专家手动定义的 ITR"放在同一把尺子下比较。你会看到两类比较方式：直接传入一个打分函数，以及接入一个完整的自定义模型；比较的核心指标是总体平均处方效应（PAPE）和处方效应曲线下面积（AUPEC）。

估计的 ITR 与用户自定义 ITR

本包允许你比较"估计得到的 ITR"与"用户自定义的 ITR"这两者的表现。estimate_itr 函数接受以下参数：

参数 说明
fit 由 estimate_itr 函数拟合得到的对象
user_itr 一个由用户定义的函数，返回一个单位级别的连续得分用于分配治疗（我们假定得分小于 0 的个体不应接受治疗）
data 一个数据框
treatment 一个字符串，指定 data 中的处理变量
outcome 一个字符串，指定 data 中的结局变量
budget 一个数值，指定在预算约束下可接受治疗的人群最大比例

该函数会返回一个对象，其中包含针对用户自定义 ITR 估计得到的 GATE、ATE 与 AUPEC。


# estimate ITR 
fit <- estimate_itr(
  treatment = "T",
  form = user_formula,
  data = star_data,
  algorithms = c("causal_forest"),
  budget = 0.2,
  split_ratio = 0.7)

# user's own ITR
score_function <- function(data){
  data %>% 
    mutate(score = case_when(
      school_urban == 1 ~ 0.1, # inner-city
      school_urban == 2 ~ 0.2, # suburban
      school_urban == 3 ~ 0.4, # rural
      school_urban == 4 ~ 0.3, # urban
    )) %>%
    pull(score) -> score
    
  return(score)
}

# evalutate ITR
compare_itr <- evaluate_itr(
  fit = fit,
  user_itr = score_function,
  data = star_data,
  treatment = "T",
  outcome = outcomes,
  budget = 0.2)

背景与解释

为什么要公平地比较"数据估计的 ITR"和"专家自定义的 ITR"？两者本质上是两种"开治疗处方"的思路：前者让算法从数据中自己学出"谁更可能获益"，后者把临床专家的经验（比如"城区学校的孩子更容易获益"）直接写进一个打分规则。要比较谁更好，关键在于用同一套标准、在同一批"未见数据"上打分。

evalITR 通过样本分割（sample splitting）保证公平：估计型 ITR 只在训练子集上拟合，然后在独立的测试子集上评估；而用户自定义的 ITR 也同样在这同一个测试子集上评估。这样，任何一方都无法"偷看"自己被评估的数据，避免了把训练误差当成真实表现。

常见误区：如果你用一个在全部数据上拟合好的模型，又在全部数据上评估它，得到的指标会系统性地偏乐观（过拟合），这时再和专家规则比就失去了意义。这也是为什么本例里 split_ratio = 0.7 这一步不能省。

我们绘制了在一系列预算约束下，用户自定义 ITR 与估计得到的 ITR 各自针对写作得分（writing score）估计出的处方效应曲线下面积（AUPEC）。图中显示，估计得到的 ITR 表现优于用户自定义的 ITR。

背景与解释

AUPEC 曲线怎么读？AUPEC（Area Under the Prescriptive Effect Curve，处方效应曲线下面积）可以理解为一张"按获益能力排座位"的图。横轴是预算（budget），也就是愿意接受治疗的人群比例，从 0 到 1；纵轴是在该预算下使用 ITR 相比"不分配治疗"所能获得的累计处方效应。

一条越高越好的曲线，意味着这个 ITR 越会把有限的治疗资源精准投给最可能获益的人。在任意预算水平上，曲线 A 若整体高于曲线 B，就说明 A 在"靶向获益"上更高效。本例里估计型 ITR 的曲线整体压在用户自定义 ITR 之上，所以结论才是"数据驱动的 ITR 表现更好"。

还要注意：如果某一段曲线跌到 0 以下，说明在这个预算范围内给患者治疗反而比不治疗更差——这就提示你当前预算下的分配方案出了问题，需要往更靠前的（更该获益的）人群收一收。

既有模型与用户自定义模型

本包还允许将既有机器学习包估计出的 ITR 与用户自定义模型进行比较。下面的代码展示了一个示例：使用 grf 包中的因果森林（causal forest），并结合样本分割。estimate_itr 函数接受以下参数：

参数 说明
treatment 一个字符串，指定 data 中的处理变量
form 一个公式，指定结局变量与协变量
data 一个数据框
algorithms 一个字符向量，指定要使用的机器学习算法
budget 一个数值，指定在预算约束下可接受治疗的人群最大比例
split_ratio 一个字符串，指定 data 中的结局变量（译者注：原文档此处描述有误，split_ratio 实际应为 0 到 1 之间的数值，表示训练/测试分割比例，详见下文说明）
user_model 一个字符串，指定用户自定义的模型

user_model 输入应当是一个接受两个参数的函数：training_data（训练数据）与 test_data（测试数据）。该函数会利用 training_data 拟合模型，再用 test_data 估计 CATE（条件平均处理效应，Conditional Average Treatment Effect）或其他关注的指标。它还应当指定如何基于估计出的效应得到 ITR。

在下面的例子中，我们通过样本分割拟合一个线性模型，并使用估计得到的 CATE。具体做法是：对 CATE 为正的个体给予治疗，对 CATE 为负的个体不给予治疗，由此得到 ITR。函数 user_model 接收训练数据与测试数据，并返回一个列表，其中包含：(1) 一个 ITR；(2) 一个拟合好的模型；以及 (3) 一个长度与输入数据相同的连续得分。

# user-defined model
user_model <- function(training_data, test_data){

  # model fit on training data
  fit <- train_model(training_data)
  
  # estimate CATE on test data
  compute_hatf <- function(fit, test_data){

    score <- fit_predict(fit, test_data)  
    itr   <- score_function(score)
    
    return(list(itr = itr, score = score))
  }

  hatf <- compute_hatf(fit, test_data)
  
  return(list(
    itr = hatf$itr, 
    fit = fit, 
    score = hatf$score))
}

注意，用户自定义的模型可以是任意能够返回一个单位级别连续得分（用于分配治疗）的模型。它不必是线性模型，也不必是估计 CATE 的模型。我们可以在 train_model 函数与 fit_predict 函数中指定自定义函数来计算得分。如果模型没有默认的 predict 函数，我们就需要用 fit_predict 写一个自定义函数。

# train model
train_model <- function(data){
  fit <- lm(
    Y ~ T*(cov1 + cov1 + cov3), 
    data = data)
  return(fit)
}

# predict function
fit_predict <- function(fit, data){
  # need to change this function if 
  # the model does not have a default predict function
  score <- predict(fit, data) 
  return(score)
}

此外，我们还可以选择任意一种评分规则，把连续得分映射为是否给予治疗的二值指示变量。

# score function
score_function <- function(score){
  itr <- (score >= 0) * 1
  return(itr)
}

如果指定了 split_ratio，函数会把数据拆分为训练集与测试集。split_ratio 应当是一个介于 0 和 1 之间的数值。与之相对，如果指定了 n_folds，函数则会通过交叉验证使用全部数据来拟合用户自定义的模型。

背景与解释

模型摘要里这些指标到底在说什么？运行 summary() 后你会看到几张"成绩单"：

PAPE（总体平均处方效应）：采用该 ITR 相比"不给任何人治疗"能让总体平均好多少，是衡量"总体获益"的核心数字。PAPEp 是在预算约束下的处方效应；PAPDp 则是两个 ITR 之间的处方效应差异（所以前面单独比较估计 ITR 与用户 ITR 时算不出 PAPDp，因为没有"两者之差"这一项）。AUPEC 是前面讲过的处方效应曲线下面积，反映整体靶向效率。GATE（分组平均处理效应）则把人群按某个协变量切成若干组，分别报告每组的处理效应，相当于更精细的亚组分析。

每一行都带 statistic 与 p.value：它们检验"该效应是否显著不同于 0"（单个 ITR）或"两个 ITR 是否真的有差异"（PAPDp）。p.value 越小，越有把握说这个效应/差异不是偶然。

背景与解释

什么时候数据驱动的规则能打败专家经验？看本例的 GATE 表很有意思：估计型 ITR（causal_forest）在各组上效应相对温和；而用户自定义模型（user_model）在第 4、5 组出现了非常大、且统计显著的正效应（如第 5 组估计值 711，p≈7e-11），但在第 1–3 组又是显著为负的"害处"。这说明一旦真实的处理效应异质性（谁获益、谁不获益）比较复杂、且和专家设想的简单规则对不上，数据驱动的方法往往能更精准地找到获益人群。

反过来，专家规则并非总是输家：如果真实的获益模式恰好和专家经验吻合（比如某个协变量确实主导了效应），在小样本下数据驱动模型容易过拟合、反而更糟，这时简洁的专家规则可能更稳。另外留意：用户自定义 ITR/模型在 PAPE 一行常显示 0.0 / NaN——这是因为它的分配规则是确定性的（给定规则就没有抽样波动），evalITR 无法为它估计标准误，属于已知的实现局限，并不代表它真的"零效应"。
