《用单一算法做交叉验证》

原文：Cross-validation with single algorithm（英文） · evalITR 官方文档中文译本

当用户选择在交叉验证（cross-validation）框架下估计并评估个体化治疗规则（Individualized Treatment Rule, ITR）时，evalITR 会调用 Imai and Li (2023) 论文中的算法 1（Algorithm 1）来完成估计与评估。关于算法 1 的更多细节，请参阅此页面。

背景与解释

为什么 ITR 评估特别需要交叉验证？核心矛盾在于「既当运动员又当裁判」：如果我们用同一批数据既学会一条个体化决策规则、又用它来打分，分数几乎必然被高估——模型会把训练样本里的噪声也「记」下来，这就是过拟合（overfitting）。与传统的平均处理效应（ATE，相当于给所有人同一种处理）相比，ITR 要为每个人定制决策，模型更灵活、也更容易过拟合。因此，评估 ITR 时更需要样本外（out-of-sample）的无偏估计，而交叉验证正是实现这一点的标准做法：用模型没见过的数据来检验它的真实表现。

与「样本分割」方式不同，这里不再指定 split_ratio 参数，而是选择折数（n_folds）。下面以 3 折交叉验证估计 ITR 为例做演示。在实际研究中，我们建议使用 10 折，以获得更稳定的模型表现。

背景与解释

K 折交叉验证是怎么「分数据」的？把全部样本随机切成 K 份（折），轮流让其中 K−1 折当「训练集」用来学习 ITR，剩下的 1 折当「验证集」用来评估；这样轮换 K 次，使每一份数据都恰好被当过一次验证集。最终把 K 次的评估结果汇总（例如取平均），就得到对整个数据的无偏估计。本例用 3 折只是为了方便演示；折数越多，估计的方差越小、结果越稳，但计算量也随之增加——这也是官方推荐 10 折的原因。

输入 R 包参数 说明
数据 Z = {X_i, T_i, Y_i}，i = 1, …, n treatment = treatment, form = user_formula, data = star_data treatment 是一个字符串，用于指定 data 中的处理变量；form 是一个公式，用于指定结局变量与协变量；data 是一个数据框
机器学习算法 F algorithms = c("causal_forest") 一个字符向量，用于指定要使用的机器学习算法
评估指标 τ_f PAPE, PAPD, AUPEC, GATE 默认值
折数 K n_folds = 3 n_folds 是一个数值，表示交叉验证所用的折数
… budget = 0.2 budget 是一个数值，表示在预算约束下可被给予处理的人群最大比例 
library(evalITR)
# 估计 ITR 
set.seed(2021)
fit_cv <- estimate_itr(
               treatment = treatment,
               form = user_formula,
               data = star_data,
               algorithms = c("causal_forest"),
               budget = 0.2,
               n_folds = 3)
#> 使用交叉验证评估 ITR ...
背景与解释

怎样得到「无偏」的 AUPEC / PAPE 估计？关键在于训练与评估在样本上严格分离：在第 k 折里，ITR 规则只在训练集上学出来，然后必须在它从未见过的第 k 折验证集上计算 PAPE、AUPEC 等指标。这样得到的指标衡量的是规则的泛化能力，而不是它对训练数据的「记忆力」。交叉验证把多折的验证结果拼起来，既利用了全部数据，又避免了「用同一数据既估计又评估」带来的乐观偏差（optimistic bias），因此 AUPEC 这类曲线下面积的估计才不会虚高。

输出是一个对象，其中包含不同指标（PAPE、PAPD、AUPEC）的估计评估量 τ̂_F 及其估计方差。

# 评估 ITR 
est_cv <- evaluate_itr(fit_cv)
#> 无法计算 PAPDp

背景与解释

交叉验证与「样本分割（split_ratio）」是什么关系？两者目的相同——都为了防止「同批数据既估计又评估」。区别在于手段：样本分割是把数据一次性切成训练/验证两块、各用一次，简单但相对浪费数据；交叉验证则通过多折「轮换」复用全部数据，估计更高效，还会顺带给出各指标的方差（见输出里的 std.deviation 一列）。此外，输出里出现 无法计算 PAPDp（Cannot compute PAPDp），是因为我们只指定了带预算约束的 budget = 0.2 版本，而未同时提供可以计算「处方效应差异（PAPDp）」所需的对照设置，属于正常提示而非报错，其余指标（PAPE、PAPEp、AUPEC、GATE）均正常输出。
